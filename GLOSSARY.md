# Agentic Trust Foundation Glossary

| Term | Meaning in this project |
|---|---|
| **ATF** | Agentic Trust Foundation; the trust/delegation/authorization layer. |
| **Authority** | Permission for a principal/agent to perform defined actions under defined constraints. |
| **Delegation** | Explicit transfer or grant of bounded authority from one principal to another. |
| **Authorization** | Evaluation of whether a requested action is permitted by the available authority and policy. |
| **Authority evidence** | Verifiable evidence describing the authority on which a downstream decision relies. |
| **Capability** | A defined action/resource permission that can be granted or evaluated. |
| **Trust domain** | A domain in which identity, evidence, policy, and trust relationships are interpreted. |
| **Provenance** | Information that records the origin and chain of evidence behind an action/decision. |
| **Revocation** | Mechanism for invalidating authority or evidence before its natural expiry. |
| **Fail-closed** | A security behavior where missing, invalid, expired, or ambiguous authority does not silently become permission. |
| **Agent-Pay** | Financial control/execution layer that consumes ATF authority and applies financial controls. |
| **Payment instrument** | A controlled mechanism used to execute a financial transaction; not authority itself. |
| **Provider** | External or simulated payment execution system used through a provider adapter. |
| **Settlement** | Process of reconciling financial obligations/results after payment execution. |
| **Reconciliation** | Comparison of internal transaction state with provider/rail financial records. |
| **Site Adapter** | Integration layer applying agentic trust semantics to websites/services. |
| **Conformance** | Automated verification that an implementation satisfies a defined protocol contract. |
| **Test vector** | Machine-readable input/expected result used to verify protocol semantics. |
| **Reference implementation** | Implementation intended to demonstrate protocol semantics; not automatically production-certified. |
| **Production evidence** | Evidence that a real deployment operates under a defined environment and acceptance criteria. |
| **Independent implementation** | An implementation created outside the Foundation repositories/organization. |
| **Independent certification** | External evaluation of interoperability, security, or conformance by a party independent of the Foundation. |
