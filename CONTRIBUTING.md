# Contributing

Thank you for contributing to Agentic Trust Foundation.

## Before opening a PR

- Read the repository README and relevant specifications.
- Keep changes scoped to one coherent problem.
- Add or update tests, schemas, vectors, or documentation when behavior changes.
- Do not commit credentials, private keys, tokens, personal data, or production secrets.
- Prefer backward-compatible changes unless a specification version explicitly permits a breaking change.

## Pull requests

Please describe:

1. What changed.
2. Why it changed.
3. Which specification or design principle it affects.
4. How it was tested.
5. Any compatibility or migration impact.

Protocol changes should include the corresponding specification, schema, example, or conformance vector when applicable.

## Design principles

Changes should preserve protocol-first design, explicit delegation, least privilege, fail-closed authorization, revocability, auditability, privacy, human control, and vendor neutrality.

## Security

Please do not disclose vulnerabilities in public issues. Follow `SECURITY.md`.
