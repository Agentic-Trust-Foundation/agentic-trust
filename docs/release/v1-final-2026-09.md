## V1 authorization semantics

Authorization outcomes are exactly:

- ALLOW
- DENY
- REQUIRE_HUMAN

Authentication is not authorization. Missing, invalid, expired, revoked, or indeterminate required authority fails closed.

Delegation is bounded authority and cannot silently exceed the authority held by the delegator.

## Agent-Pay boundary

ATF publishes the normalized semantic authority contract consumed by Agent-Pay. Agent-Pay owns financial policy and execution; ATF owns general authority.

V1 intentionally does not freeze one universal ATF credential or signature wire format. Implementations may use different credential mechanisms if they preserve the normative semantics and applicable conformance requirements.

## Security boundary

Credential verification, revocation and delegation-chain validation are normative requirements. A verifier must fail closed when a required security fact cannot be established.

## Non-goals

V1 does not require:

- one hosted ATF service;
- one identity provider;
- one credential/token format;
- one agent runtime;
- one payment provider;
- centralized reputation;
- mandatory SaaS infrastructure.

## Change-control rule

Do not reopen the complete V1 review for normal documentation, test, example, or implementation hardening work.

A proposed semantic change must be classified as:

1. documentation clarification;
2. non-breaking implementation hardening;
3. optional extension/profile; or
4. V2 semantic change.

Breaking semantic changes require a new protocol version or explicit versioned architecture decision.
